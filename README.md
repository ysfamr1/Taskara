## 1. الملفات
| الملف | الوصف |
|---|---|
| `requirements.txt` | قائمة المكتبات المطلوبة (`pip install -r requirements.txt`) |
| `main.py` | **الكود الكامل في ملف واحد** (إعدادات + قاعدة البيانات + المنطق + Discord + الاختبارات) |

> لا يوجد `.env` ولا `config.py`. كل الإعدادات في أعلى `main.py` (القسم `1. SETTINGS & CONSTANTS`).

```bat
pip install -r requirements.txt
```
(أو يدويًا: `pip install "discord.py>=2.4,<3" "cryptography>=42" "pytest>=8"`)

## 3. إعداد Discord Developer Portal
1. افتح <https://discord.com/developers/applications> ثم **New Application** وسمِّه `Tazkara`.
2. من القائمة الجانبية افتح **Bot**:
   - اضغط **Reset Token** وانسخ التوكن **مرة واحدة**. لا ترسله لأي أحد ولا تضعه في صورة أو في GitHub.
   - أوقف **Public Bot** إن كنت لا تريد أن يضيفه غيرك.
   - في **Privileged Gateway Intents**:
     - ✅ **MESSAGE CONTENT INTENT**: **إلزامي**. بدونه تصل الرسائل فارغة، فيكون الـ Transcript ناقصًا، **ولن يحذف البوت أي قناة** (حماية مقصودة).
     - ⬜ **SERVER MEMBERS INTENT**: اختياري. فعّله فقط إذا جعلت `ENABLE_MEMBERS_INTENT = True` في `main.py` (يجعل خيار «إغلاق عند مغادرة صاحب التيكت» فوريًا بدل الفحص الدوري كل 10 دقائق).
     - ⬜ **PRESENCE INTENT**: غير مستخدم، اتركه مُعطّلًا.
3. من **OAuth2** انسخ **Client ID** (أو Application ID من General Information).
4. رابط الدعوة (ضع الـ ID مكان `APP_ID`):
```
https://discord.com/oauth2/authorize?client_id=APP_ID&permissions=361045806096&scope=bot+applications.commands
```
### الصلاحيات (Integer = `361045806096`)
| الصلاحية | السبب |
|---|---|
| View Channels | رؤية الكاتيجوري وقنوات النشر واللوج |
| Send Messages | رسالة التحكم والتنبيهات |
| Embed Links | الـ Embeds |
| Attach Files | رفع ملف الـ Transcript في قناة اللوج |
| Read Message History | قراءة رسائل التيكت لبناء الـ Transcript |
| Manage Channels | إنشاء قنوات التيكت وحذفها |
| Manage Roles | ضبط Permission Overwrites على قنوات التيكت فقط (البوت **لا** يعدّل الرولات ولا يمنحها لأحد) |
| Create Private Threads | الخطة البديلة: فتح التيكت كـ Thread خاص عندما يرفض Discord إنشاء قناة |
| Send Messages in Threads | الكتابة داخل تيكت الـ Thread |
| Manage Threads | قفل وفتح وحذف تيكت الـ Thread، وإضافة الستاف إليه |
**لا** تمنح البوت `Administrator`. البوت لا يحتاجه، وإعطاؤه إياه يوسّع الضرر لو سُرق التوكن.
### إعداد السيرفر بعد الدعوة
1. أنشئ **Category** للتيكتات (مثل `🎫 التيكتات`) وامنح رول البوت داخلها: View Channels وSend Messages وEmbed Links وAttach Files وRead Message History وManage Channels وManage Permissions.
2. أنشئ **قناة لوج خاصة** (لا يراها إلا الإدارة والبوت). نسخ الـ Transcripts فيها **غير مشفّرة** لأنها داخل Discord.
3. قناة نشر البانل: يملك البوت فيها View وSend وEmbed Links وRead History، **و** Create Private Threads وSend Messages in Threads وManage Threads (للخطة البديلة). يجب أن تكون قناة نصية عادية، وليست Announcement.
   > **إن كان البوت مضافًا من قبل:** لا داعي لطرده. افتح Server Settings ← Roles ← رول Tazkara، وفعّل الصلاحيات الثلاث الجديدة، أو أعد الدعوة بالرابط الجديد أعلاه.
4. ملاحظة: الكاتيجوري في Discord تتسع لـ 50 قناة كحد أقصى، لذلك حد التيكتات المفتوحة لكل بانل بين 1 و50.

## 5. مفتاح التشفير (للنسخ المحلية)
```bat
python main.py --init-key
```
- يُنشأ مفتاح عشوائي في:
  - **Windows:** `%LOCALAPPDATA%\Tazkara\keys\archive.key`
  - Linux/macOS: `~/.config/tazkara/archive.key`
- يرفض الأمر الكتابة فوق مفتاح موجود، ويرفض أي مسار داخل مجلد `archives/`.
- **مسار مخصص (اختياري):** متغير بيئة نظام التشغيل `TAZKARA_ARCHIVE_KEY_FILE` (من «Edit the system environment variables»، **وليس** ملف `.env`).
- **قيّد الوصول للمفتاح على Windows** (من CMD):
  ```bat
  icacls "%LOCALAPPDATA%\Tazkara\keys\archive.key" /inheritance:r /grant:r "%USERNAME%:R"
  ```
- **انسخ المفتاح احتياطيًا Offline** (USB أو مدير كلمات مرور) **بعيدًا عن** `data.db` و`archives/`. ضياع المفتاح = استحالة قراءة النسخ المحلية. وتسرّبه مع الأرشيف = لا فائدة من التشفير.
- فك تشفير نسخة محلية عند الحاجة:
  ```bat
  python main.py --decrypt archives\g123\ticket5_a7_abcd.html.enc ticket5.html
  ```
  الملف الناتج سري لأنه يحتوي محادثات.

## 6. التشغيل على Windows 10 (خطوة بخطوة)
1. ثبّت Python من <https://www.python.org/downloads/windows/> وفعّل ✅ **Add python.exe to PATH** أثناء التثبيت.
2. أنشئ مجلدًا مثل `C:\Tazkara` وضع فيه `main.py` و`requirements.txt`.
3. افتح **CMD** داخل المجلد (اكتب `cmd` في شريط العنوان في File Explorer ثم Enter).
4. أنشئ بيئة افتراضية وثبّت المكتبات:
   ```bat
   py -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
5. شغّل الاختبارات (دون توكن ودون إنترنت):
   ```bat
   pytest main.py -q
   ```
   المتوقع: `35 passed`.
6. أنشئ مفتاح التشفير: `python main.py --init-key` ثم انسخه احتياطيًا (§5).
7. ضع التوكن في `main.py` (§4).
8. افحص الإعدادات: `python main.py --check`. المتوقع: `config OK, db integrity=ok, permissions integer=361045806096`.
9. شغّل البوت: `python main.py`
10. في السيرفر اكتب `/setup`. قد يتأخر ظهور الأمر حتى ساعة عند المزامنة العامة. للتطوير ضع ID سيرفرك في `DEV_GUILD_ID` ليظهر فورًا.
11. **الإيقاف الآمن:** `Ctrl+C` في نافذة CMD. المهام المجدولة محفوظة في القاعدة وتُستأنف عند التشغيل التالي.
**للتشغيل الدائم:** الجهاز يجب أن يبقى يعمل ومتصلًا. عطّل وضع السكون (Settings ← System ← Power & sleep ← Never). يمكن استخدام **Task Scheduler**: Create Task ← Trigger: *At startup* ← Action: `C:\Tazkara\.venv\Scripts\python.exe` مع Arguments: `main.py` وStart in: `C:\Tazkara` ← فعّل «Run whether user is logged on or not».
> ⚠️ لا تشغّل نسختين من البوت بنفس `data.db` في نفس الوقت.

## 7. استخدام `/setup`
الأمر متاح فقط لمن يملك **Manage Server**، ويُتحقق من الصلاحية على الخادم مع **كل** ضغطة، وليس عند فتح اللوحة فقط. اللوحة مخفية (ephemeral).
- **بانل جديدة:** معالج من 4 خطوات:
  1. النصوص وقالب اسم القناة (`{number}` و`{user}` و`{panel}`).
  2. رولات الإدارة والستاف والكاتيجوري.
  3. قناة النشر وقناة اللوج.
  4. الحد الأقصى للتيكتات المفتوحة والخمول والـ SLA والتصعيد، ثم خيار «إغلاق عند مغادرة صاحب التيكت» (**افتراضيًا معطّل**)، ثم **حفظ ونشر**.
  - كل مدخل يُتحقق منه، وكذلك ملكية القنوات والرولات لنفس السيرفر وصلاحيات البوت **الفعلية** في كل قناة.
- **إدارة البانلات:** تعديل، إعادة نشر، إيقاف/تفعيل، أرشفة، حذف الإعدادات. الأرشفة والحذف **مرفوضان** ما دامت هناك تيكتات نشطة أو قيد الأرشفة.
- **الإحصائيات:** التيكتات حسب الحالة، متوسط أول رد، آخر 7 أيام، تجاوزات SLA، الأرشفة المعلّقة، النسخ المحتجزة.
### الخطة البديلة: Threads خاصة 🧵
Discord قد يرفض إنشاء قنوات جديدة لساعات (حد معدّل قد يصل إلى 24 ساعة)، أو تمتلئ الكاتيجوري (50 قناة)، أو يمتلئ السيرفر (500 قناة). في هذه الحالات يحدث التالي **تلقائيًا**:
- يُفتح التيكت كـ **Thread خاص** داخل قناة البانل. لا يراه إلا صاحب التيكت والبوت ومن يملك Manage Threads، ومن ينضم إليه من الستاف.
- يصل إلى قناة اللوج تنبيه بالتيكت الجديد (مع منشن رولات الستاف) وزر **«انضم للتيكت»**. البوت يتحقق من أن الضاغط ستاف لهذه البانل قبل إضافته.
- كل شيء آخر كما هو: Claim وHold وClose وReopen والأرشفة المزدوجة والحذف بعد التحقق والرسالة الخاصة.
- أثناء الحظر لا يطلب البوت قنوات من Discord إطلاقًا، وعند انتهائه يعود تلقائيًا إلى القنوات العادية.
- لإيقاف الخطة البديلة: `THREAD_FALLBACK_ENABLED = False` في أعلى `main.py`.
### دورة حياة التيكت
- **فتح:** قناة خاصة بصاحب التيكت والستاف والإدارة فقط، وتيكت نشط **واحد** لكل مستخدم في كل بانل (مضمون بفهرس UNIQUE في القاعدة وليس بالكود فقط).
- **Claim:** للستاف فقط، ولا يستطيع صاحب التيكت استلام تيكته. **Hold:** يوقف كل المؤقتات ولا يُحتسب وقته. **Close:** بتأكيد. **Reopen:** للستاف قبل اكتمال الأرشفة.
- **بعد Close:** تُقفل الكتابة ← يُبنى Transcript (HTML آمن) ← نسخة في قناة اللوج + نسخة مشفّرة محليًا ← التحقق من الاثنتين بالـ SHA-256 ← **عندها فقط** تُحذف القناة ← رسالة خاصة مختصرة لصاحب التيكت (رقم وحالة ووقت فقط، وفشلها لا يوقف شيئًا).
- إذا فشلت أي نسخة: القناة **تبقى**، وتُعاد المحاولة تلقائيًا بتأخير متزايد (حتى ساعة) وتُستأنف بعد إعادة التشغيل.
- إذا كانت مرفقات أكبر من الحد: تتوقف الأرشفة ويظهر زر **«إقرار الأدمن والمتابعة»** لإدارة البانل فقط.

## 8. النسخ الاحتياطي والاستعادة
### ما الذي يُنسخ؟
| العنصر | أين | ملاحظات |
|---|---|---|
| `data.db` | مجلد البوت | كل الحالات والإعدادات والمهام |
| `archives/` | مجلد البوت | مشفّرة. بلا المفتاح لا فائدة منها، وهذا مقصود |
| `archive.key` | `%LOCALAPPDATA%\Tazkara\keys\` | **في مكان منفصل** عن الاثنين أعلاه |
| `main.py` | مجلد البوت | احفظ نسخة **بدون التوكن** (أعِد `placeholder`) |
### نسخ احتياطي والبوت يعمل (آمن مع WAL)
```bat
python -c "import sqlite3; s=sqlite3.connect('data.db'); d=sqlite3.connect('backup-data.db'); s.backup(d); d.close(); s.close(); print('ok')"
```
ثم انسخ `backup-data.db` ومجلد `archives\` إلى قرص خارجي. **لا تنسخ `data.db` بالنسخ العادي أثناء التشغيل**، فقد تكون آخر التغييرات في `data.db-wal`.
### الاستعادة
1. أوقف البوت (`Ctrl+C`).
2. احذف `data.db` و`data.db-wal` و`data.db-shm`، وضع النسخة الاحتياطية باسم `data.db`.
3. أعِد مجلد `archives\` وتأكد أن المفتاح في مكانه.
4. `python main.py --check` ثم `python main.py`.
5. عند التشغيل يقوم البوت بـ**المصالحة**:
   - التيكتات التي حُذفت قنواتها تتحول إلى `LOST`.
   - قنوات التيكت التي لا يعرفها البوت تُحذف **فقط إن لم يكتب فيها إنسان قط**، وإلا تُترك ويُسجَّل تحذير.
   - ⚠️ عند استعادة نسخة **قديمة**: راجع يدويًا قنوات التيكت التي أُنشئت بعد تاريخ النسخة واحذف أو أرشف ما لا تحتاجه قبل فتح تيكتات جديدة، لأن أرقام التيكتات الجديدة قد تتطابق مع علامات قنوات قديمة.

## 9. ما تم اختباره وما لم يُختبر (بصدق)
**تم تشغيله فعليًا** (`pytest main.py -q`: **35 passed**، ثابت في 5 تشغيلات متتالية، تفاصيلها في `TEST_RESULTS.txt`):
الاختبارات العشرون المطلوبة كلها، بالإضافة إلى: Triggers القاعدة لمنع الانتقالات الخاطئة، وسباق Reopen مع اكتمال الأرشفة، ورسائل جديدة بعد بناء الـ Transcript، وإقرار المرفقات الناقصة، وغياب MESSAGE_CONTENT، وعدم تسريب الأسرار في السجلات، ورفض الـ placeholder، والصلاحيات الدنيا.
وأيضًا: `pyflakes` بلا أخطاء، وفحص يدوي لأوامر `--init-key` و`--check` و`--decrypt`، ومحاولة تسجيل دخول حقيقية إلى Discord بتوكن مزيف (رُفض كما يجب، وأُغلق البوت بأمان، ولم يظهر التوكن في السجل).
**لم يُختبر** (الاختبارات تستخدم `FakeGateway` بدل Discord):
- `DiscordGateway` الفعلية: إنشاء القنوات والـ Overwrites والرفع والتنزيل والقفل.
- **وضع الـ Threads الخاصة** على Discord حقيقي (إنشاء الـ Thread، وإضافة صاحب التيكت والستاف، والقفل، والحذف). تحققت فقط من مطابقة الاستدعاءات لمكتبة discord.py 2.7.1.
- الأزرار والقوائم والنوافذ (Modals) و`/setup` على سيرفر حقيقي.
- حدود المعدّل (Rate limits) الحقيقية من Discord. الاختبار يحاكي الأخطاء فقط.
- التشغيل على **Windows** (الاختبارات شُغّلت على Linux).
- التشغيل الطويل (أيام) والسيرفرات الكبيرة. البوت لا يدعم Sharding (حتى 2500 سيرفر).
## 10. القيود المعروفة
- `find_log_copy` يبحث عن العلامة في آخر 100 رسالة من قناة اللوج فقط. في قناة لوج مزدحمة جدًا قد يُرفع الـ Transcript مرتين بعد خطأ شبكة غامض (تكرار، **وليس فقدانًا**).
- لا يوجد ضمان «مرة واحدة بالضبط» (exactly-once) لأي عملية خارجية. التصميم يضمن **عدم الفقد** و**عدم حذف القناة قبل التحقق**، ويجعل التكرار نادرًا.
- من يملك `Administrator` في السيرفر يرى كل قنوات التيكت دائمًا (قيد من Discord). البوت ينبّه عن ذلك عند الحفظ.
- المرفقات أكبر من 8MB أو فوق ميزانية حجم الرفع لا تُضمَّن، ويلزم إقرار صريح من إدارة البانل.

## 12. حل المشكلات
| العرض | السبب والحل |
|---|---|
| `BOT_TOKEN is still the placeholder` | ضع التوكن في `main.py` (§4) |
| `Login failed` | التوكن خاطئ أو أُعيد تعيينه: Reset Token وضعه من جديد |
| `PrivilegedIntentsRequired` | فعّل MESSAGE CONTENT INTENT في Developer Portal |
| `key file not found` | `python main.py --init-key` أو صحّح `TAZKARA_ARCHIVE_KEY_FILE` |
| `/setup` لا يظهر | انتظر حتى ساعة، أو ضع `DEV_GUILD_ID`، وتأكد من scope `applications.commands` |
| التيكت عالق في «جارٍ الإغلاق» | راجع السجل: غالبًا صلاحيات قناة اللوج، أو مساحة القرص، أو مرفقات تنتظر إقرار الأدمن. القناة لن تُحذف حتى يُحل السبب، وهذا مقصود |
| «Discord أوقف مؤقتًا إنشاء قنوات جديدة» أو في السجل `rate_limited retry_after=86xxx` | حد من Discord نفسه على إنشاء القنوات (قد يصل إلى 24 ساعة)، وليس خطأ في الإعدادات. التيكتات الجديدة تُفتح تلقائيًا كـ Threads خاصة (انظر «الخطة البديلة»). إن ظهرت هذه الرسالة للأعضاء فهذا يعني أن الخطة البديلة لا تعمل: امنح البوت في قناة البانل Create Private Threads وSend Messages in Threads وManage Threads |
| «تيكت جديد فُتح كـ Thread خاص» في قناة اللوج | الخطة البديلة تعمل. اضغط «انضم للتيكت» لتدخل إليه |
| البانل «MISCONFIGURED» | قناة أو كاتيجوري حُذفت أو نقصت صلاحية: `/setup` ← إدارة ← تعديل، ثم تفعيل |
